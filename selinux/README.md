# Fiorino SELinux policy

This directory contains the policy source for the `fiorino-decrypt` domain:

- `fiorino_decrypt.te` — type-enforcement rules;
- `fiorino_decrypt.fc` — file-context mappings;
- `fiorino_decrypt.if` — policy interfaces.

The policy labels `/usr/local/bin/fiorino-decrypt` as the executable type and
`~/.fiorino` (including its contents) as `fiorino_vault_t`. The decrypt domain
can manage files in that vault type and can write restored plaintext only under
SELinux-labeled user-home directories. The domain is enforcing; it is not
marked permissive.

## Build the policy module

Install the SELinux policy development tools, then run from this directory:

```bash
make -f /usr/share/selinux/devel/Makefile fiorino_decrypt.pp
```

This creates `fiorino_decrypt.pp`. The `.if` file is consumed by the policy
Makefile and does not need separate compilation.

## Generate the manual page

```bash
sepolicy manpage -p . -d fiorino_decrypt_t
```

This creates `fiorino_decrypt_selinux.8`, which can be viewed with:

```bash
man ./fiorino_decrypt_selinux.8
```

## Install and label the policy

```bash
sudo semodule -X 400 -i fiorino_decrypt.pp
sudo restorecon -F -R -v /usr/local/bin/fiorino-decrypt
sudo restorecon -F -R -v "$HOME/.fiorino"
```

The vault mapping uses `HOME_DIR` with a `system_u` source context so SELinux generates it alongside
the other home-directory mappings in `file_contexts.homedirs`. A literal
`/home/[^/]+` rule stays in the base mappings and can be overridden by the
generated generic `user_home_t` home-directory rule.

The vault mapping deliberately omits the file-type field so it matches both
`~/.fiorino` directories and their contents. A `--` field would match only
regular files, leaving directories labeled `user_home_t`. Rebuild and reinstall
the module after changing its file-context mappings, then run `restorecon`.

Check the expected and actual vault directory labels:

```bash
matchpathcon "$HOME/.fiorino" "$HOME/.fiorino/default"
ls -Zd "$HOME/.fiorino" "$HOME/.fiorino/default"
```

Both should show type `fiorino_vault_t` for existing matching paths.

Check that the module is loaded:

```bash
semodule -l | grep fiorino
```

The RPM spec and helper script generated by `sepolicy generate` are not needed
for this direct module-installation workflow.

## Remove the policy

```bash
sudo semodule -r fiorino_decrypt
```
